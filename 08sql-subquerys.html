    Subconsultas¶

    La subconsulta se encierra entre paréntesis.  La cláusula order by no puede ir en una subconsulta.  A excepción del operador EXISTS, deben producir una sola columna de datos como resultado.  Una subconsulta puede contener a otra subconsulta y ésta a otra y así n veces. Límite: según SGBDR.

    https://mariadb.com/kb/en/subqueries/:

    • Escalar: devuelven un valor

    Operadores¶

    El resultado de una subconsulta puede ser un único valor o varios valores.  Para subconsulta de un solo valor:  Operadores de relación: =,<,>,<>,>=,<=  Para subconsulta de ninguno o más valores:  IN, ANY, ALL, EXISTS.

    -- Cantidad de hijos máximo
select max(numhi) from empleado
-- Empleado con más hijos
select nomemp from empleado where numhi =
(select max(numhi) from empleado);
-- Empleados con menos hijos que 'Saladino Mandamás, Augusto'
select nomemp from empleado where numhi <
(select numhi from empleado where nomemp = "Saladino
Mandamás, Augusto");

     [NOT] IN: Verdadero si el valor comparado coincide con alguno de los valores de la columna resultante de la subconsulta.

    select nomdep from departamento where codcen in (

    ANY¶

     ANY: Devuelve verdadero si la comparación se cumple para alguno de los valores resultantes de la subconsulta.

    select codcen from centro where pobcen='Murcia'); -- Nombres y departamentos de los empleados cuyo sueldo -- es superior a alguno de sus compañeros de departamento. select nomemp,coddep from empleado e where salemp > any ( select salemp from empleado where coddep=e.coddep);

    ALL¶

    ALL: Devuelve verdadero si la comparación se cumple para todos los valores resultantes de la subconsulta. -- Nombre, salario y código de departamento de los empleados que tienen el -- mayor sueldo de su departamento. select nomemp,salemp,coddep from empleado e where salemp >= all (select salemp from empleado where coddep=e.coddep); -- Mismo resultado select nomemp, salemp, coddep from empleado e where salemp = (select max(salemp) from empleado where coddep=e.coddep);

    EXISTS¶

     [NOT] EXISTS: Devuelve verdadero si la subconsulta obtiene algún resultado (alguna fila).  No evalúa ninguna comparación  Hay que enlazar la consulta principal con la subconsulta -- Nombre y departamento de los empleados para los que exista otro -- empleado que se haya incorporado a la empresa antes que ellos -- (e.fecinemp es la fecha de incorporación a la empresa del empleado -- que se está evaluando en la consulta principal o externa). select nomemp,coddep from empleado e where exists (select * from empleado where fecinemp < e.fecinemp);

    CTE¶

    Tablas derivadas  Colocar una subconsulta en vez de una tabla en la clausula from.  La tabla derivada debe ir entre paréntesis y tener un alias para poder referenciarla. -- Empleados que ganaban el máximo en cada departamento. -- Con subconsulta select nomemp, salemp, coddep from empleado e where salemp = (select max(salemp) from empleado where coddep=e.coddep); -- Con tabla derivada select nomemp,salemp,coddep from empleado e, (select max(salemp) max from empleado where coddep=e.coddep) empmax where e.salemp=empmax.max;

    Columnas

    TYPE: tipo de acceso  ALL: full scan (a evitar, lee todos los registros)  INDEX: full index scan (a evitar, se utilizan todos los accesos de un índice)  ref: utiliza un índice  POSSIBLE_KEYS: índices candidatos  ROWS: filas afectadas

    Índices¶

    Al buscar un valor concreto en una columna de una tabla, si la columna no tienen un índice, hay que recorrer toda la tabla comparando fila a fila.  Si la tabla tiene pocas filas no hay problema.  Solución: Crear un índice para cada columna que se utiliza en la clausula WHERE.  Los índices se comportan como punteros sobre las filas de la tabla y nos permiten determinar rápidamente cuáles son las filas que cumplen la condición de la cláusula WHERE.

    No es conveniente crear un índice para cada una de las columnas de una tabla  El exceso de índices innecesarios pueden provocar un incremento del espacio de almacenamiento y una penalización en el rendimiento ya que el SGBD debe decidir qué índices necesita utilizar.  Además añaden una sobrecarga a las operaciones de inserción, actualización y borrado, porque cada índice tiene que ser actualizado después de realizar cada una de estas operaciones.

    Índices en MariaDB¶

    La mayoría utilizan B-TREES  PRIMARY KEY  UNIQUE  INDEX  FULLTEXT  Existen otros tipos de índice (usan otros tipos de almacenamiento): SPATIAL, MEMORY

     https://mariadb.com/kb/en/create-index/  CREATE INDEX nombreIndice ON tabla(columna)

    CREATE INDEX idx_pais ON oficina(pais)

    Forzando consultas¶

    https://mariadb.com/kb/en/index-hints-how-to-forc e-query-plans/  STRAIGHT_JOIN: fuerza el orden de unión de las tablas (la izquierda se lee antes que la derecha)  select nombre, apellido1, email, ciudad from empleado e straight_join oficina o on e.codigo_oficina=o.codigo_oficina where pais="España";

    Forzando índices¶

    USE INDEX: fuerza que se utilice un índice  Se pone después de la tabla que contiene el índice  select nombre, apellido1, email, ciudad from oficina o use index (idx_pais) join empleado e on e.codigo_oficina=o.codigo_oficina where pais="España";  IGNORE INDEX: fuerza que NO se utilice un índice

    Gestión de índices¶

     https://mariadb.com/kb/en/optimize-table/  OPTIMIZE TABLE nombreTabla;  Permite desfragmentar una tabla, así como actualizar y reordenar los índices.  https://mariadb.com/kb/en/analyze-table/  ANALYZE TABLE nombreTabla;  Analiza y almacena la distribución de claves en una tabla.  Se usa para determinar el orden que el servidor seguirá para combinar tablas en un JOIN y qué índices se usarán en una consulta.

    Índice FULLTEXT¶

     https://mariadb.com/kb/en/full-text-index-overview /  Mejora la búsqueda de partes de texto en un campo (sentencias LIKE)  Cambiar LIKE por consulta mediante MATCH (campo) AGAINST (valorABuscar)

    CREATE FULLTEXT INDEX idx_nombre_descripcion ON producto(nombre, descripcion); SELECT * FROM producto WHERE MATCH(nombre, descripcion) AGAINST ('madera'); SELECT * FROM producto WHERE MATCH(nombre, descripcion) AGAINST ('M%');

    Consultas y DML/DLL¶

    Insertando datos a partir de subconsultas  https://mariadb.com/kb/en/insert-select/  INSERT tabla SELECT  INSERT tabla(campos) SELECT insert cliente(codigo_cliente, nombre_cliente, telefono, fax, linea_direccion1, ciudad) select e.codigo_empleado*100, e.nombre, o.telefono, o.telefono, o.linea_direccion1, o.ciudad from empleado e join oficina o on e.codigo_oficina=o.codigo_oficina where e.codigo_oficina="MAD-ES";

    Modificando/Borrando datos a partir de una subconsulta  Dentro del WHERE se puede utilizar una subconsulta  Algunos SGBD no permiten modificar/eliminar los datos que se están leyenda en la subconsulta.

    delete from cliente where codigo_cliente not in (select codigo_cliente from pedido)

    Creando tablas a partir de consultas  CREATE TABLE nombreTabla [IGNORE | REPLACE] [AS] SELECT…

    create table director as select e.nombre, e.apellido1, e.apellido2, e.email from empleado e where e.puesto like "%Director%";

    Actividades¶

    • AC801. (RABD.3 // CE3a, CE3b // 3p) Sobre la base de datos empresa, realiza las siguientes consultas:

      1. Lista el nombre de todos los departamentos que hay en la tabla departamento.
      2. Lista los nombres y los presupuestos de todos los departamentos.
      3. Lista todas las columnas de la tabla departamento.
      4. Lista el nombre de los empleados junto con su salario.
      5. Recupera todas las posibilidades de número de hijos que tienen los empleados (debes recuperar 0, 1 y 2).
      6. Lista el nombre y el complemento familiar (= salario * nº hijos * 4 /100) de todos los empleados.
      7. Lista el nombre de los departamentos, el precio en euros y el precio en dólares estadounidenses (USD).
      8. A partir de la consulta anterior, utiliza los siguientes alias para las columnas: nombre de departamento, euros, dólares.
